# 原项目「摄像头手势识别与手势操作」实现分析

> 分析对象：`globe-main/_副本`（深空制图仪）— 核心实现全部在 `sketch.js`（约 4250 行），
> 依赖随仓库分发的本地 MediaPipe Hands（`assets/mediapipe/`）。
> 本文是把它的手势链路完整拆开，作为本扩展 `engine/gesture-engine.js` 移植的依据。

## 1. 总体管线

```
getUserMedia 摄像头流 → 隐藏 <video>
      │  (30fps 节流、逐帧去重、busy 标志)
      ▼
MediaPipe Hands.send({image: video})   ← 浏览器本地 WASM 推理，21 个 3D 关键点
      ▼
onResults 回调 → 单手锁定 → 手势形态判定(比耶/捏合/五指) → 手掌运动分析(平滑+死区)
      ▼
动作触发(带滞后阈值/双击窗口/长按计时/冷却) → 地球仪旋转·缩放·模式切换·流星雨
```

关键设计：**「形态」与「运动」两条判定线并行**。
捏合、比耶、五指聚拢看的是 21 点的几何比例；转动、滚动看的是掌心坐标的时序运动。
两条线通过「手掌静止时才允许缩放」「比耶激活期间屏蔽运动判定」等互斥规则避免串扰。

## 2. 摄像头调用（setupCamera / maintainCamera / restartCamera）

- `navigator.mediaDevices.getUserMedia({ video: { facingMode:'user' } })`；
  桌面端先 `enumerateDevices()` 挑一个有名字的内置/外接摄像头（`preferredDesktopCamera`），
  避免选中虚拟摄像头；移动端不指定设备。
- **generation 计数器**：每次重建摄像头/识别实例就 `++generation`，所有异步回调先比对
  generation，不匹配直接丢弃 — 防止旧实例的迟到回调污染新状态。这是全文反复使用的防竞态模式。
- video 元素隐藏挂载 + `playsinline`，监听 `ended/error/emptied/stalled` 记录失效时刻；
  失效超过 2.2s → `restartCamera()`（限 2 次重试，退避 600ms）。
- `document.hidden` 时暂停送帧（省电且不后台抢占 CPU）。

## 3. 识别模型与初始化（initHands）

- MediaPipe Hands（legacy solutions API），**全部资源本地化**（hands.js + WASM + tflite），
  无网络依赖 — 这正是适合打包进浏览器扩展的形态。
- `maxNumHands: 1`、`modelComplexity: 0`（轻量模型，帧率翻倍且够用）、
  `minDetectionConfidence / minTrackingConfidence = 0.6`（低于常见默认 0.5 会误检、过高会丢手）。

## 4. 帧调度与健康自愈（feedHands / checkHandsHealth / recoverHands）

这一层是"稳定不卡死"的关键，扩展里原样保留：

- 30fps 节流 + `video.currentTime` 未变不重发 + `handsBusy` 单飞标志（一次只允许一个 send 在途）。
- 超时自检：首次结果前容忍 15s（加载模型），之后 send 超 2.5s 无返回视为卡死；
  曾出过结果但 3s 无新结果也判异常。
- 连续失败 3 次进入恢复流程：销毁旧实例 → 指数退避重连（600/1200/2500ms）→ 3 次后降级为
  「鼠标模式」并给出人话提示。恢复成功则所有计数器清零。

## 5. 单手锁定（onHandResults 开头）

按 handedness（Left/Right）锁定当前控制手；另一只手入画被直接忽略；
**锁定手连续离开画面 900ms 后**才允许换手 — 防止双手交替导致控制对象乱跳。

## 6. 几何原语

| 函数 | 做法 | 用途 |
| --- | --- | --- |
| `palmCenter` | 手腕 + 4 个掌指关节取平均 | 手掌位置（运动判定的探针） |
| 掌心尺寸 `palm` | ‖手腕(0) − 中指根(9)‖ | **一切距离的归一化分母** → 远近手不敏感 |
| `fingerExtension(tip,pip)` | 指尖/指PIP 到手腕距离比 | 手指伸/收 |
| `fingerStraight(tip,mcp)` | 手腕→mcp 与 mcp→tip 向量夹角余弦 | 手指是否笔直（防"半弯"误判） |
| `handDist3` | 含 z 的 3D 距离 | 全捏合判定（平面投影会重叠误判） |

## 7. 各手势的判定逻辑与防误触参数

### 7.1 比耶 ✌️（流星雨 → 本项目映射为关标签页）
食指+中指伸直（extension>1.10 且 straight>0.56）、无名指+小指收拢（<1.04）、
两指尖分叉 > 0.18×掌心。形状成立后**持续保持 420ms** 才触发；一次保持只触发一次；
触发后 3500ms 冷却。判定成立期间 `return`，同帧屏蔽转动/缩放 — 防止 V 字手移动手掌时联动其它动作。

### 7.2 拇指食指双捏 👌（进观察者模式 → 缩放复位）
`捏合距离/掌心 < 0.45` 记为闭合，**回升 > 0.58 才算释放**（迟滞回差防临界抖动连续误触发）；
要求至少一根其余手指伸展（和五指收拢手势区分）。两次"闭合沿"间隔在
120ms（防单帧抖动算两次）~1600ms（防两个无关单捏凑成双击）之间 → 判为双击；
每次闭合后 520ms 内封锁五指缩放。

### 7.3 五指聚合度 → 缩放（本项目同名映射）
`fiveSpread = 五指尖到指尖质心平均距离 / 掌心尺寸`。防误触链条：
手掌平移 > 0.0055/帧 时暂停（先静止才能缩放）→ 变化 < 0.004 死区丢弃 →
单帧 > 0.08 限幅（防抽风）→ 冲量累积（±2.5 封顶）而不是绝对值映射（画面不会自己一路放大）。

### 7.4 手掌运动 → 转动（本项目映射为滚动）
先做**自适应指数平滑**：位移小 alpha→0.22（滤抖），位移大 alpha→0.82（保跟手）。
再进**静止死区状态机**：位移 < 0.0009（放大时加宽）→ 锁死输出；锁死后需 > 1.7 倍死区才解锁
（迟滞）。横向移动中纵向分量占比 < 0.18 直接归零，浅斜向需连续 2 帧同向才放行。
输出还要换算成"每帧速度"并做 0.90 动量 EMA — 甩一下之后球还会继续转。

### 7.5 观察者模式内横扫切城（本项目映射为切标签页）
「待命→起笔→总位移→冷却→重新待命」状态机：
触发一次后 `disarm`，需位移 < 0.006 连续 2 帧（停稳）且回手靠近起笔锚点（或停稳 8 帧）才重新 `arm`；
方向用**起笔到当前位置的总位移**主轴判定，而不是瞬时速度 — 回手过程中的反向动作不会抢判；
需 ≥2 帧且总位移 > 阈值；两次切换间强制 520ms 冷却。

### 7.6 五指全捏合（3D 校验，防投影重叠误判）+ 持续 5 帧 / 捏合后 2.2s 窗口内两次方向反转（摆手）→ 退出。
本项目未移植（与"收拢缩小"存在语义冲突，砍掉以降误触面）。

### 7.7 手离开画面
所有状态机复位（捏合周期、比耶保持、平滑缓存、待命标志），但保留"模式"类状态 — 手回来即继续，
不会因丢跟踪半途炸状态。

## 8. 降级策略
识别库缺失 / 初始化失败 / 重连耗尽 → 明示"已切到鼠标模式"，功能不崩，只是少一种输入。
本扩展对应降级为：面板显示错误 + 鼠标键盘正常浏览不受任何影响（扩展不拦截任何输入）。
